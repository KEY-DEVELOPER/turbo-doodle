# ADR 0001 — Wave 1 foundation conventions

- Status: Accepted (Architect, Wave 1). Items marked **OPEN** need a human decision.
- Date: 2026-09-28
- PRD: §5.2–5.5, §9.0, §13.7, §14.1–14.6, §14.10

## Decisions

1. **ULIDs are stored as `CHAR(26) COLLATE "C"`** (`app.core.types.ULIDType`), generated by
   `app.core.ids.new_ulid()` (monotonic within a process). Readable in SQL/API, and the "C"
   collation makes text order equal time order. Cost: 26 bytes vs 16 for a binary UUID;
   revisit if `odds_snapshot` index size becomes a problem.
2. **Timestamps** use `UTCDateTime` (TIMESTAMPTZ). Naive datetimes are rejected on write
   (`NaiveDatetimeError`), never guessed.
3. **Bitemporal = system time.** `BitemporalMixin` adds `valid_from`/`valid_to`; the current
   row has `valid_to IS NULL`; a partial unique index keeps one current row per business key
   (`__bitemporal_key__`). Corrections go through `app.core.bitemporal.supersede()` / `close()`.
   A DB trigger (`edgeledger_bitemporal_guard`) allows only `valid_to: NULL → value`; DELETE
   and TRUNCATE are rejected.
4. **Append-only tables** attach `edgeledger_forbid_mutation` via
   `app.core.ddl.append_only_triggers(table)` (UPDATE/DELETE/TRUNCATE rejected + REVOKE from
   PUBLIC). Applied now to `audit_log`, `event_status_history`, `kickoff_history`. Owners of
   `odds_snapshot`, `prediction`, `opportunity_evaluation`, `signal`, `ledger_entry`, raw
   fetches, etc. must do the same in their migrations.
5. **Monthly partitions**: `edgeledger_ensure_monthly_partitions(parent, from_month, months)`,
   children named `<parent>_yYYYYmMM`. The spine migration creates previous month + 15 ahead
   for `audit_log`. **No DEFAULT partition** (a default partition makes later partition creation
   fail once it holds rows). **OPEN:** a scheduled job must call
   `app.core.ddl.ensure_monthly_partitions` (e.g. monthly, 12 months ahead) — owner of the
   scheduler task, before month 15 after the first deploy.
6. **Error format**: `app.core.errors.AppError(code, message, details, status_code)`; every
   error (including 404/422/500) renders `{"error": {"code", "message", "details"}}`. Codes are
   UPPER_SNAKE and stable.
7. **Settings**: `app.core.config.Settings`, env prefix `EDGELEDGER_`, secrets as `SecretStr`.
8. **Where the spine tables live**: `source` → `sources`; sport/competition/season/team/
   team_alias/venue/bookmaker/bookmaker_ruleset/**source_entity_map** → `reference`;
   event + histories → `events`; market/selection → `markets`; audit_log → `audit`. Every
   module's models are registered in `app/all_models.py`.
9. **Football is seeded** in the spine migration with fixed id `01K6ARCH00000000000000SPRT`.
10. **`source` licence flags have no defaults**, and a CHECK prevents `enabled = true` without a
    non-empty `licence_ref` (DATA-01 AC1 at DB level; connector validation is still DATA-01).
11. **Import-linter contracts** (`backend/.importlinter`) encode CLAUDE.md §4. Extra choices:
    - `app.core` imports no domain module; domain modules never import `app.api`/`app.main`.
    - "markets/features/models know nothing about users" = may not import identity, betting,
      ledger, settlement, analytics, notify, wellbeing.
    - "pato never feeds models" = features/models may not import pato. A validated-cohort path
      needs a new ADR and an explicit `ignore_imports` entry.
    - betting may not import models, features or sources (predictions are read via
      opportunities).
    - `app.ledger.models` is protected: only `app.ledger` (and `app.all_models`) may import it;
      settlement and others use `app.ledger.service`. A placeholder `ledger/models.py` exists so
      the contract is active before LED-01.
    - Not expressible as imports (enforced by runtime tests later): notify → wellbeing check;
      wellbeing cannot be disabled by others; betting never *updates* quotes (DB triggers).
12. **Tests**: DB tests create a throwaway database per session on
    `EDGELEDGER_TEST_DATABASE_URL`, so parallel worktrees don't collide; skipped locally when
    the server is unreachable, mandatory in CI (`EDGELEDGER_REQUIRE_DB=1`). A drift test and
    `alembic check` in CI make sure models and migrations agree; another test enforces a single
    Alembic head.
13. **Tooling**: `uv` (lock file `backend/uv.lock`) for Python; npm for the frontend.
    Next.js 16.3 + React 19.2, Vitest + Testing Library, `openapi-fetch` with types from
    `openapi-typescript`. The generated client and `frontend/openapi.json` are committed and
    CI fails if stale.
14. **MinIO image**: MinIO stopped publishing official Docker images in 2025
    (`minio/minio` no longer pulls). Local compose uses Chainguard's free `chainguard/minio`
    and `chainguard/minio-client`. **OPEN:** confirm acceptable, or switch to another
    S3-compatible server; production uses managed S3-compatible storage anyway.
15. **RG-08 linter** (`tools/banned_terms.py`, terms in `tools/banned_terms.toml`): stdlib-only,
    whole-word, case-insensitive; scans frontend sources/public/locales, backend string
    literals (not code or docstrings), backend templates, `docs/user/`, `marketing/`.
    Exemption only via `banned-terms-allow: <reason>` on the same line.
    **OPEN (product):** Italian equivalents chosen by the Architect — `garantito/a/i/e`,
    `blindato`, `senza rischi`, `rischio zero`, `scommessa/vincita/quota/pronostico sicura`,
    `colpo sicuro`, `non puoi perdere`, `soldi facili/gratis`, `il fisso`/`fisso del giorno`,
    `vittoria/vincita certa`, `guadagno facile`. Plain `sicuro`/`certo` are *not* banned
    (too many neutral uses, e.g. "pagamento sicuro", "un certo numero"). English "certain" is
    banned as a whole word per PRD, which also flags neutral phrases like "a certain number".

## Consequences

- Any change to `app/core/`, `.importlinter`, `tools/banned_terms.toml` or this ADR needs the
  Architect.
- Workers (Dramatiq/APScheduler), SQLAdmin, auth/RLS helpers and object-storage clients are
  not scaffolded yet; the first task that needs each adds it (with Architect review for core).
